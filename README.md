## 1. 项目简介

**AI 网页翻译助手**（Web Page Full Translator）是一个运行在浏览器脚本管理器里的单文件油猴脚本。它把当前网页的正文切分、送给你自己配置的大模型接口翻译，再以**双语对照**或**仅译文替换**的方式写回页面。

### 它解决什么问题

- **不想把整页内容交给第三方翻译服务**：翻译请求只发往你填写的接口地址，API Key 只存在本机脚本存储中，脚本本身不含任何统计或遥测。
- **想用自备的模型**：DeepSeek、智谱 GLM、Kimi、通义千问、Gemini、Claude 中转，以及本机 Ollama / vLLM / LM Studio 等，只要实现 `POST /v1/chat/completions` 即可接入。
- **想双语对照读技术文档**：英文文档保留原文、译文以浅色块紧随其下，便于对照与引用。
- **不想装客户端或扩展**：一个 `.user.js` 文件即全部，无构建、无打包、无外部资源（不加载 CDN、字体或图片）。

### 能力边界

翻译质量、速度与费用完全取决于你配置的模型与端点；脚本负责的是**文本抽取的准确性**、**请求调度的效率**与**回写时页面结构的完整性**。翻译文本的版权归原作者，请遵守目标站点的服务条款与 robots 约定。

## 2. 主要功能特性

### 2.1 翻译能力

| 特性  | 说明  |
| --- | --- |
| 任意 OpenAI 兼容端点 | 接口地址、API Key、模型名三项全部可自定义 |
| 目标语言自由设置 | 面板内置 15 种常用语言的输入建议，也可填入任意语言名称 |
| 自定义翻译指令 | 内置提示词已按「只输出 JSON 数组、不写开场白、保持段落结构与标点风格、保留专有名词/代码/网址」打磨，可整体替换 |
| 原文语言智能跳过 | 段落若已是目标语言则不再请求，直接节省 token |
| 尊重站点翻译标记 | 遵循 `.notranslate`、`[translate="no"]`，避免与站点自身的翻译声明冲突 |
| 代码与界面元素跳过 | 默认跳过 `pre/code/textarea/input` 等代码与输入区，以及 `nav/aside/button/header/footer` 等界面元素（可关闭） |
| 行内结构不碎片化 | 同一容器内的多个文本节点（如「阅读<a>文档</a>」）合并为一次翻译，避免逐词翻译导致语义割裂 |

### 2.2 显示与交互

| 特性  | 说明  |
| --- | --- |
| 双语对照 / 仅译文替换 | 一键切换；双语模式在原文段落下方追加译文块 |
| 替换模式的多节点原位映射 | 段落内含链接、徽章、图标时，按标记协议逐节点原位改写文本，**不破坏元素结构** |
| 悬浮球 | 可拖拽，位置自动记忆；进度以百分比显示，悬停可见「已处理/总数 · 当前并发」 |
| 快捷键 Alt+T | 三级循环：开始翻译 → 停止 → 还原原文 |
| 油猴菜单入口 | 翻译本页 / 还原原文 / 翻译设置 |
| RTL 语言支持 | 阿拉伯语等目标语言自动标注 `dir="rtl"` 与 `lang` |
| 深色模式跟随 | 跟随系统配色；移动端与窄屏自适应 |
| SPA 页面跳转保护 | 路由变化时自动还原译文，避免译文与内容错位 |
| UI 完全隔离 | 界面挂在 Closed Shadow DOM 中，与页面样式互不干扰 |

### 2.3 性能与稳定性（v1.1.0 重点）

| 特性  | 说明  | 收益  |
| --- | --- | --- |
| 全局去重 | 跨分块、跨容器合并重复文本，同一文本只请求一次 | 重复文案多的页面请求数与 token 直接下降 |
| 分块上限提升 | 单请求 2600 字符 / 32 段（旧版 1200 / 24） | 请求数约减半，省去对应的往返延迟与重复系统提示词开销 |
| LPT 调度 | 按分块体积降序发出，长块优先占用并发窗口 | 整页完成时间更短 |
| 动态并发（AIMD） | 起始并发 5，连续成功后逐级升至上限 10；遇 429 降并发并全局冷却 2 秒 | 端点宽松时吞吐近线性上升；限频时不触发雪崩 |
| 流式增量渲染 | 基于 SSE 逐项解析并立即上屏 | 首段可见时间从「整块完成」降到「首项完成」 |
| 双传输通道 | `fetch` 优先（HTTP/2 连接复用、支持流式），失败自动回退 `GM_xmlhttpRequest` | 兼顾速度与兼容性 |
| 失败二分降级 | 整批失败则对半拆分重试（最多 3 层） | 上下文超长等问题只重试失败的一半 |
| 漏项补发 | 仅补发缺失项，最多一次 | 流式截断不会导致整批重来 |
| 分片持久缓存 | 16 个分片、LRU 上限 3000 条、脏分片增量写、900 ms 去抖 | 重复访问同一站点近乎瞬时；不再周期性整表序列化 |
| 渲染分帧 | 按帧 8 ms 时间预算批量执行 DOM 写入 | 长页面翻译时页面不卡顿 |
| 采集优化 | 排除元素集合 + 子树剪枝 + WeakMap 记忆化 | 大页面文本采集耗时下降一个量级 |

### 2.4 隐私

- API Key 与全部翻译缓存只写入本机脚本存储（油猴管理器或 `localStorage`）。
- 除你配置的接口地址外，脚本不向任何第三方发送数据，不加载远程脚本或资源。

**方式 A：一键安装（推荐）**

在脚本管理器已安装的前提下，用浏览器打开下面的链接，管理器会弹出安装页：

```
https://raw.githubusercontent.com/YOUR_GITHUB_NAME/ai-web-translator/main/ai-web-translator.user.js
```

**方式 B：手动新建**

1. 打开脚本管理器面板（如 Tampermonkey → 「添加新脚本」）。
2. 清空编辑器内容，粘贴脚本全文。
3. `Ctrl/Cmd + S` 保存。

1. 点击页面右侧悬浮球 → 菜单选择 **翻译设置**。
2. 在「接口配置」区填写：**API 接口地址**、**API Key**、**模型名称**。
3. 在「翻译选项」区确认目标语言（默认「简体中文」）与显示模式（默认「双语对照」）。
4. 点击 **测试连接**，等待右侧出现 `✓ 连接成功 · 1.2s` 字样。
5. 点击 **保存**。

设置保存在脚本存储键 `wbtf_settings` 中，保存后立即生效，无需刷新页面。

> 若测试连接失败，请先用浏览器或 `curl` 直接验证该接口与 Key 是否可用，再回到本脚本排查。

## 5. 使用方法及示例

### 5.1 三种触发入口

| 入口  | 操作  |
| --- | --- |
| 悬浮球 | 单击打开菜单 → 翻译本页 / 还原原文 / 显示模式 / 翻译设置 |
| 快捷键 `Alt + T` | 开始翻译 → 停止 → 还原原文，循环切换 |
| 油猴菜单 | 在脚本管理器扩展菜单中点击「▶ 翻译本页」等条目 |

悬浮球状态：

| 显示  | 含义  |
| --- | --- |
| `译` | 空闲，可开始翻译 |
| `42%` 等进度数字 | 翻译中，悬停可见「已处理/总数 · 当前并发 a/b」 |

### 5.2 双语对照模式

原始 HTML：

```html
<p>Hello world</p>
```

翻译后（译文块以 `display:block` 追加在原文下方，透明度 0.66）：

```html
<p data-wbtf-done="1">Hello world<span class="wbtf-tr" translate="no" lang="zh-CN">你好，世界</span></p>
```

### 5.3 仅译文替换模式

**单文本节点**——直接改写文本值，零结构改动：

```html
<!-- 原文 -->    <h2>Getting Started</h2>
<!-- 译文 -->    <h2 data-wbtf-done="1">快速开始</h2>
```

**段落内含行内元素**——按标记协议原位改写，链接与图标保持原样：

```html
<!-- 原文 -->
<p>Read the <a href="/docs">documentation</a> first.</p>

<!-- 发送给模型的请求串：把段落内各文本节点编号 -->
["<0>Read the </0><1>documentation</1><2> first.</2>"]

<!-- 模型回传：<0>请先阅读</0><1>文档</1><2>。</2> → 逐节点原位写入 -->
<p data-wbtf-done="1">请先阅读<a href="/docs">文档</a>。</p>
```

**标记解析失败时的降级**（模型漏标记、多标记或重排序时触发，保证页面不被破坏）：

```html
<p data-wbtf-done="1">
  <span class="wbtf-orig">Read the <a href="/docs">documentation</a> first.</span>
  <span class="wbtf-tr-full" translate="no">请先阅读文档。</span>
</p>
```

### 5.4 场景示例

**示例 1：英文技术文档双语阅读**

1. 打开英文文档页。
2. 设置中显示模式选「双语对照」，目标语言「简体中文」，模型建议选长文性价比高的（如 `deepseek-chat`、`glm-4-flash`）。
3. `Alt + T` 开始。首段通常在 1–3 秒内出现，其余段落陆续填充。
4. 阅读完毕后再按一次 `Alt + T` → 停止，再按一次 → 还原原文。

**示例 2：日文 / 韩文页面整页替换**

1. 目标语言设为「简体中文」，显示模式设为「仅译文替换」。
2. 若页面有站内导航或侧边广告需要保留原样，在「自定义排除选择器」中填入选择器（见 5.6）。

**示例 3：列表 / 商品页（观察去重收益）**

这类页面往往存在大量重复文案（「加入购物车」「查看详情」「Read more」）。脚本会把这些重复文本合并为一次请求，结果广播回所有位置。翻译结束后 Toast 会显示「重复合并 N」，N 即被合并的重复段数。

**示例 4：单页应用（SPA）**

路由切换时脚本会自动还原上一次的译文，避免旧译文残留在新页面上。切换后重新按 `Alt + T` 即可翻译新内容。

### 5.5 自定义翻译指令示例

在「自定义翻译指令」中填写下列模板之一即可覆盖内置提示词。`{{lang}}` 会被替换为目标语言（`{{target}}` 为同义占位符）。

**模板一：口语化、保留术语**

```
把下列 JSON 数组中的每个字符串翻译成{{lang}}，语气口语化、自然，像技术博客。
专业术语与品牌名保留英文原文。只输出 JSON 数组，不要任何解释或代码围栏。
```

**模板二：附带术语表**

```
你是{{lang}}技术文档译者。严格遵守以下术语表：
pipeline = 流水线；rollback = 回滚；tenant = 租户。
把下列 JSON 数组逐项翻译成{{lang}}，保持条目数量与顺序不变，只输出 JSON 数组。
```

**模板三：保留 Markdown 结构**

```
把下列 JSON 数组中的每个字符串翻译成{{lang}}。
保留其中的 Markdown 标记（如 **粗体**、`代码`、[链接](url)）的位置与形式不变。
只输出 JSON 数组。
```

> 自定义指令时请务必保留「只输出 JSON 数组、条目数量与顺序不变」的要求，否则解析会失败。若请求串中包含 `<0>` 形式的标记，脚本会自动追加标记保留规则。

### 5.6 自定义排除选择器示例

每行一个 CSS 选择器，`#` 开头为注释：

```
# 保留侧边栏与广告位原文
.sidebar
# 保留代码示例区
.highlight-block
# 保留评论区
#comments
.no-translate
```

### 5.7 性能调优建议

| 场景  | 建议  |
| --- | --- |
| 端点限频严格（免费额度） | 并发改为 2–3，关闭「并发自适应」或接受其自动降级 |
| 端点宽松、追求速度 | 并发 8–10，保持「并发自适应」开启 |
| 长文章、模型上下文大 | 「单次请求最大字符数」提到 4000–6000（失败会自动二分重试） |
| 短文案为主的列表页 | 保持默认 2600 字符 + 32 段封顶即可 |
| 推理型模型（响应慢） | 「请求超时」提到 180–300 秒；关闭流式更稳妥 |
| 接口不支持 SSE | 传输方式改为「仅 GM_xmlhttpRequest」；脚本也会按响应 `content-type` 自动降级 |

## 7. 实现架构概览

理解下面这条链路，就能快速定位任何问题所在的环节：

```
collectTargets()          采集：TreeWalker + 排除集合剪枝 + WeakMap 记忆化
      │                   产出 [{host, text, nodes, req, mnodes}]
      ▼
groupTargets()            全局去重：按 req 合并为组，重复文本共用一次请求
      │
      ▼
makeChunks()              分块：2600 字符 / 32 段封顶 + LPT 降序排序
      │
      ▼
动态并发池 (AIMD)          acquireSlot/finally releaseSlot + 429 冷却
      │
      ▼
processChunk()            命中缓存立即提交；未命中走 requestTranslate()
      │
      ▼
requestTranslate()        重试 → 二分降级 → 漏项补发；产出与请求等长的结果数组
      │
      ▼
callOnce()                fetch（可流式）/ GM_xmlhttpRequest（自动回退）
      │
      ▼
readSSE()                 SSE 逐行解析 → createArrayStreamer() 增量切分数组元素
      │                    （严格按元素序号回调，解析失败占位为空）
      ▼
commitGroup()             写缓存 + 广播到该组所有宿主 + 计数
      │
      ▼
渲染队列（每帧 8 ms）     renderTranslation() 双语追加 / 换模式原位改写
      ▼
records[]                 还原所需的全部句柄（元素引用，无需再查询）
```

关键函数与职责：

| 函数  | 职责  |
| --- | --- |
| `collectTargets()` | 定位所有待翻译段落并合并同容器文本节点 |
| `groupTargets()` / `makeChunks()` | 去重与分块调度 |
| `createArrayStreamer()` | 流式 JSON 数组增量解析（严格的元素序号对齐） |
| `readSSE()` | SSE 读取与思考块剥离 |
| `fetchCall()` / `gmCall()` | 两条传输通道 |
| `requestTranslate()` | 重试、二分降级、漏项补发 |
| `acquireSlot()` / `noteError()` / `noteSuccess()` | 动态并发与限频自适应 |
| `commitGroup()` / `processChunk()` | 结果落地与缓存写入 |
| `renderTranslation()` / `restoreAll()` | 渲染与还原 |
| `cacheGet()` / `cachePut()` / `saveCacheNow()` | 分片缓存读写与增量落盘 |

## 8. 常见问题解答

### Q1 提示「网络错误或接口不可达」

按顺序排查：接口地址是否写全 `/v1/chat/completions`；本机能否访问该域名（代理/防火墙）；端点是否需要特定请求头。**注意**：油猴环境的 `fetch` 受 CORS 约束，`GM_xmlhttpRequest` 不受约束 —— 若某端点不允许浏览器直连，把「传输方式」改为「仅 GM_xmlhttpRequest」即可。

### Q2 提示 HTTP 401 / 403

Key 错误、过期或额度耗尽。这类错误被判定为致命错误，脚本会立即终止本轮翻译而不做无意义重试。请重新获取 Key 并在面板中更新后重试。

### Q3 流式输出不生效（没有逐段秒出）

流式依赖 `fetch` 通道与端点的 SSE 支持。请确认：传输方式不是「仅 GM_xmlhttpRequest」；「流式增量输出」为开；端点确实返回 `text/event-stream`。脚本会检查响应 `content-type`，网关忽略 `stream` 参数直接返回 JSON 时会自动降级为整块解析。

### Q4 本地 Ollama 连不上

浏览器页面发起的跨域请求会被 Ollama 默认策略拦截。启动 Ollama 时设置允许来源，例如：

```bash
# Windows (PowerShell)
setx OLLAMA_ORIGINS "*"
# macOS / Linux
OLLAMA_ORIGINS="*" ollama serve
```

重启 Ollama 后，面板中传输方式选「仅 GM_xmlhttpRequest」更稳妥，API Key 留空即可。

### Q5 页面部分内容没有被翻译

依次检查：该元素是否被判定为代码块 / 界面元素（可关闭「跳过代码块」「跳过导航栏页脚按钮」）；元素是否处于 `display:none` 或 `visibility:hidden`（不可见内容默认跳过）；是否命中 `.notranslate`、`[translate="no"]`；是否被「自定义排除选择器」匹配；文本是否已被判定为目标语言（中文页面混排英文时会跳过中文段）。

### Q6 如何确认译文与段落一一对应、没有错位

流式解析器严格按「元素序号」回调，即使某个元素 JSON 非法也会占位为空并交由补发机制处理，因此不存在把 A 段译文写到 B 段的可能。若观察到大面积错位，通常是页面在翻译过程中做了动态重排（无限滚动、虚拟列表），此时按 `Alt+T` 还原后重新翻译即可。

### Q7 翻译后页面空白或样式错乱

极少数站点会在框架层面（React/Vue 等）直接操作与其虚拟 DOM 冲突的文本节点。可按 `Alt+T` 还原原文；如问题稳定复现，请把该站点地址与页面结构特征反馈到 Issue。

### Q8 只想翻译正文，怎么配置

在「自定义排除选择器」中加入需要保留的区域（`.sidebar`、`#comments`、`footer` 等），或反过来在页面结构上确认正文容器；同时保持「跳过导航栏、页脚、按钮」为开。

### Q9 大概要花多少钱

费用 ≈ 总输入 token + 总输出 token 的单价之和。脚本已经做了三件省钱的事：跳过重复文本、跳过已是目标语言的段落、缓存命中不重复请求。翻译一篇 3000 词的英文文章，通常输入 6000–12000 token、输出 3000–6000 token；具体成本请按所用服务商价目表估算。

### Q10 配置保存后又变回默认示例值

这是**运行环境问题，而非保存逻辑问题**，已被浏览器实测定位。真实原因通常是下面两种之一：

1. **重复安装了两份脚本**（例如旧版本与当前版本同时启用）。两份脚本共用同一个存储键，且都在页面加载时把配置读进各自内存、之后不再回读；悬浮球坐标由同一字段恢复、默认落点相同，所以两个球完全重叠，你无法从视觉上判断点到了哪一份。此时旧实例的一次「显示模式」点击即可用它内存里的旧值（往往是默认示例值）整体覆盖你的新配置。
  自检方法：在页面按 F12，控制台执行
  
  ```js
  document.querySelectorAll('#wbtf-host').length
  ```
  
  返回 1 为正常；大于 1 请到脚本管理器中卸载多余的那份，只保留一个。
2. **脚本存储写入失败**（隐私模式、存储被禁、配额受限等）。请确认油猴管理器中的「存储」面板里 `wbtf_settings` 确实包含你的接口地址。

### Q11 如何彻底清空缓存

设置面板 → 「高级」 → 「清空翻译缓存」。缓存分 16 片存储，该操作会把全部分片写为空对象。

### Q12 支持手机浏览器吗

支持具备脚本管理器（如 Kiwi、Firefox for Android + Tampermonkey）的移动浏览器。界面已做窄屏与触摸适配，设置项在窄屏下自动堆叠为单列。

### Q13 能否翻译 PDF、本地文件或图片中的文字

不能。脚本只处理 DOM 文本节点，无法读取 PDF 画布、`canvas` 内容或本地文件；图片文字需要先经 OCR 转为可选中文本。

### Q14 提示「模型返回内容无法解析为 JSON 数组」

模型没有按要求输出 JSON（常见于能力较弱的小模型，或自定义指令未强调输出格式）。处理方式：换用指令遵循能力更强的模型；在自定义指令中加强「只输出 JSON 数组，不要任何解释与代码围栏」；或降低「单次请求最大字符数」以减少输出长度。脚本会自动二分重试，仍失败则该批标记为失败并在收尾 Toast 中报数。

### Q15 翻译到一半能取消吗

可以。`Alt+T`、悬浮球菜单的「停止翻译」都会立即中断在途请求并停止调度；已翻译的内容保持不动，可继续按 `Alt+T` 还原。

### 代码约定

- **单文件交付**：不引入构建步骤、打包器或任何运行时依赖。
- **保持 IIFE 结构**：所有代码包裹在 `(function () { 'use strict'; ... })();` 中，避免污染页面全局。
- **DOM 查询必须限定在 Shadow Root 内**：优先使用 `shadowRoot.getElementById` / `shadowRoot.querySelector`，绝不用裸 `document.querySelector` 去命中脚本自己的 UI。
- **事件与定时器必须可回收**：新增的监听器、`requestAnimationFrame`、`setTimeout`、`AbortController` 都要能随实例销毁，避免页面生命周期内泄漏。
- **失败不得破坏页面**：任何解析、渲染、回写操作都要有 try/catch 兜底并降级，宁可不翻译也不能毁掉原页面。
- **注释使用中文**，并在关键设计处说明「为什么这么做」，而非只描述「做了什么」。
- 兼容目标：现代浏览器（支持 `async/await`、`Map/Set/WeakMap`、`AbortController`）。不使用需要编译的新语法（如装饰器、`??=`）。

## 附录 B. 存储键与数据结构

| 存储键 | 内容  | 说明  |
| --- | --- | --- |
| `wbtf_settings` | JSON 对象 | 全部配置项，见附录 A |

缓存键的构成：`'c' + hash(模型 | 目标语言 | 生效提示词 | 原文)`。因此**更换模型、目标语言或翻译指令后旧缓存自动失效**，不会出现「改了指令却仍命中旧译文」的情况。
